AI 零基础入门课程 · ERP 架构师版

学员画像：ERP 架构师，有系统设计、数据库、业务流程、集成经验，无 AI 相关经验
课程目标：从零建立 AI 知识体系，理解机器学习/深度学习/大模型原理，能结合 ERP 场景设计 AI 应用方案
版本：7 天速览版 + 21 天系统版（建议走 21 天）
每日投入：约 2–3 小时（1 小时理论 + 1 小时实践 + 30 分钟考核）

1.1 贯穿主线项目：智能采购助手（螺旋式学习）

本课程最重要的学习设计：21 天不是 21 个孤立 demo，而是围绕同一个 ERP 场景层层叠加 AI 能力。每天学到的技术，都是给同一个项目"加装一个模块"。这样知识会像滚雪球一样积累，而不是学完就忘。

项目背景

一家制造企业的采购到付款（P2P）流程存在四个痛点：

痛点 现状 期望
价格异常难发现 采购价靠人工比对，异常发现滞后 AI 自动识别异常价格并预警
发票处理慢 人工录入 + 三单匹配，时效 2 天 OCR+LLM 自动识别录入
制度查询难 采购制度散落在文档，靠问人 RAG 智能问答
下单重复劳动 采购员逐单手工录入 ERP Agent 自动调 ERP API 下单

如何使用这张路线图
  1. 每天开课前：看一眼"今天给项目加装什么模块"，带着目标学
  2. 每天实践时：尽量把 demo 往"采购助手"场景上靠（哪怕只是换个数据集）
  3. 每周回顾：画一次项目当前的能力草图，看它从 v0.1 长到了什么程度
  4. 结业时：你的 Day 21 方案，就是这条主线的最终形态

若你所在企业的 ERP 方向不是采购，可选择替代主线：财务主线（智能对账→发票→财报）、供应链主线（需求预测→库存→供应商）。方法完全一致，只是场景替换。

二、21 天系统版 · 每日课程

模块 M1：AI 基础与机器学习入门

Day 1｜AI 全景图：ERP 架构师的第一堂 AI 课
  • 学习目标：建立 AI、ML、DL、生成式 AI 的概念边界，理解 AI 发展脉络
  • 核心知识点：
  • AI 的三次浪潮（符号主义→统计学习→深度学习）
  • AI / ML / DL / 生成式 AI / LLM 的关系（用金字塔图理解）
  • 监督学习、无监督学习、强化学习的区别
  • AI 能做什么、不能做什么（边界意识）
  • 关联 ERP：AI 如何重构 ERP 的"预测、决策、自动化"能力
  • 主线项目：梳理"智能采购助手"的 4 个痛点，判断哪些是 AI 可解问题（需求分析）
  • 实践：用 ChatGPT/豆包/文心一言做一次对话，记录你的感受（不评价对错，只记录）
  • 阅读：《人工智能：一种现代方法》第 1–2 章（或公众号综述文替代）
Day 2｜机器学习核心概念：数据、特征、模型
  • 学习目标：理解"特征工程"这一 ML 灵魂，掌握训练/验证/测试集划分
  • 核心知识点：
  • 样本、特征、标签的定义
  • 训练集 / 验证集 / 测试集的划分原则
  • 过拟合与欠拟合、偏差-方差权衡
  • 评估指标：准确率、精确率、召回率、F1、AUC（分类）；MAE、RMSE、R²（回归）
  • 关联 ERP：物料主数据分类 = 多分类问题；销售预测 = 回归问题
  • 主线项目：把"采购价格"拆成特征（供应商、品类、季节、数量）与标签（是否异常）
  • 实践：在 Excel/表格里手工拆分一个"客户流失"数据集，标注特征和标签
  • 工具：了解 scikit-learn（Python ML 库）的存在与定位
Day 3｜经典机器学习算法
  • 学习目标：掌握 5 类常用算法的原理与适用场景
  • 核心知识点：
  • 线性回归 / 逻辑回归（基础中的基础）
  • 决策树与随机森林（可解释性强，企业最爱）
  • KNN（实例学习）
  • K-Means 聚类（无监督）
  • 朴素贝叶斯（文本分类经典）
  • 关联 ERP：用随机森林做"采购价格异常检测"
  • 主线项目：用随机森林训练第一版采购价格异常检测模型（v0.1）
  • 实践：用云端 Notebook 跑一个 scikit-learn 自带的鸢尾花分类 demo（复制粘贴运行即可）
  • 国外：Google Colab
  • 国内：阿里云 PAI-DSW / 百度 AI Studio / 本地 Jupyter
  • 工具：scikit-learn（Python ML 库）；云端 Notebook 环境见第六章工具对照表
Day 4｜模型优化与可解释性
  • 学习目标：理解调参、交叉验证、模型可解释性
  • 核心知识点：
  • 超参数与超参数搜索（Grid Search / Random Search）
  • 交叉验证（K-Fold）
  • 特征重要性、SHAP 值（企业落地必懂）
  • 模型部署的简单流程
  • 关联 ERP：为什么"AI 黑箱"在企业审计中是大问题
  • 主线项目：对异常检测模型调参，并用 SHAP 解释"为何判定为异常"（v0.2）
  • 实践：在 Notebook 中对 Day 3 的模型做一次超参数搜索，观察准确率变化
  • 国外：Google Colab
  • 国内：本地 Jupyter / PAI-DSW
Day 5｜机器学习小结 + 第一次小测
  • 复习：M1 全部知识点串讲
  • 主线项目：端到端串起"数据→特征→模型→评估"的异常检测流程（v0.3）
  • 实践：完成一个端到端小项目——"员工离职预测"（用公开数据集 HR Analytics）
  • 考核：M1 周测（见考核部分）

模块 M2：深度学习与神经网络

Day 6｜神经网络基础：从感知机到多层网络
  • 学习目标：理解神经网络的数学直觉（不要求推导，但要懂）
  • 核心知识点：
  • 神经元、权重、偏置、激活函数（Sigmoid / ReLU）
  • 前向传播、损失函数、反向传播（直觉理解即可）
  • 梯度下降、学习率
  • 为什么深层网络比浅层强
  • 关联 ERP：神经网络适合处理"高维、非线性、海量"数据，如海量日志异常检测
  • 主线项目：理解神经网络，为 D7 发票图像识别做技术储备
  • 实践：用 TensorFlow Playground（网页版）调参数，观察分类边界变化
  • 链接：https://playground.tensorflow.org
Day 7｜卷积神经网络 CNN 与计算机视觉
  • 学习目标：理解 CNN 原理，知道图像 AI 能做什么
  • 核心知识点：
  • 卷积、池化、全连接层的作用
  • CNN 经典架构（LeNet、ResNet 一句话了解）
  • 图像分类、目标检测、图像分割的区别
  • 预训练模型与迁移学习
  • 关联 ERP：质检场景——用视觉检测产品缺陷替代人工
  • 主线项目：用 CNN 识别发票/单据图像，自动提取采购信息（v0.4）
  • 实践：在云端 Notebook 跑一个预训练 ResNet 做图片分类 demo
  • 国外：Google Colab（需 GPU 运行时）
  • 国内：百度 AI Studio（免费 GPU）/ 阿里云 PAI-DSW
Day 8｜循环神经网络 RNN 与序列数据
  • 学习目标：理解处理"序列"的神经网络
  • 核心知识点：
  • RNN、LSTM、GRU 的直觉
  • 序列数据的处理（文本、时间序列）
  • 注意力机制的引入动机（为 Transformer 铺垫）
  • 关联 ERP：时间序列预测——需求预测、库存预测
  • 主线项目：用 LSTM 预测采购价格/需求趋势（v0.5）
  • 实践：用 LSTM 跑一个简单的股价/销量预测 demo
Day 9｜Transformer 架构（重点）
  • 学习目标：掌握 Transformer，这是所有现代 LLM 的基础
  • 核心知识点：
  • Self-Attention（自注意力）机制的直觉
  • Encoder-Decoder 结构
  • 为什么 Transformer 比 RNN 快且效果好
  • 位置编码、多头注意力
  • 关联 ERP：理解 Transformer 是理解大模型的钥匙
  • 主线项目：理解 Transformer，为 D10 合同/发票文本理解打下基础
  • 实践：阅读《The Illustrated Transformer》图文博客（强烈推荐）
  • 链接：https://jalammar.github.io/illustrated-transformer/
Day 10｜深度学习小结 + 第二次小测
  • 复习：M2 全部知识点
  • 主线项目：用预训练模型做合同/发票文本理解（v0.6）
  • 实践：用预训练模型完成一个"图片描述生成"小 demo
  • 考核：M2 周测

模块 M3：大语言模型（LLM）与生成式 AI

Day 11｜大语言模型原理
  • 学习目标：理解 LLM 是什么、怎么训练出来的
  • 核心知识点：
  • GPT 系列、BERT、LLaMA 的区别（Decoder-only / Encoder-only）
  • 预训练（Pre-training）+ 微调（SFT）+ 人类反馈强化学习（RLHF）
  • Token、词表、上下文窗口（Context Window）
  • 参数量与能力的关系（Scaling Law）
  • 关联 ERP：理解"为什么大模型能写代码、写文档"
  • 主线项目：明确"智能采购助手"该选哪种 LLM、能力边界在哪（技术选型）
  • 实践：对比同一个问题在 ChatGPT、Claude、豆包上的回答差异
Day 12｜Prompt Engineering（提示词工程）
  • 学习目标：掌握与 LLM 高效沟通的方法论
  • 核心知识点：
  • Zero-shot / Few-shot / CoT（思维链）
  • Prompt 结构：角色、任务、上下文、约束、输出格式
  • 常见技巧：角色设定、分步拆解、提供示例、约束格式
  • 防幻觉技巧
  • 关联 ERP：用 Prompt 让 LLM 生成采购单、审批意见、SQL
  • 主线项目：用 Prompt 把采购员的自然语言需求转成结构化采购单（v0.7）
  • 实践：写一个"ERP 需求分析师"的 Prompt，让它输出某模块的需求文档
Day 13｜RAG（检索增强生成）
  • 学习目标：理解企业落地 AI 最关键的技术——RAG
  • 核心知识点：
  • 为什么需要 RAG（知识过时、私有数据、幻觉）
  • RAG 流程：文档切分 → 向量化 → 向量数据库 → 检索 → 生成
  • Embedding（嵌入向量）是什么
  • 向量数据库（Milvus、Pinecone、Chroma）
  • RAG 评估指标
  • 关联 ERP：把企业制度文档喂给 LLM，做"智能问答助手"
  • 主线项目：搭建"采购制度/合同智能问答"RAG 模块（v0.8）
  • 实践：用 LangChain + 一个本地 PDF，搭建最简 RAG demo
  • 国外：Google Colab + OpenAI API
  • 国内：本地 Jupyter + 智谱/通义/豆包 API（Embedding 用国内模型）
Day 14｜AI 生成内容（图像、视频、语音、代码）
  • 学习目标：了解多模态生成 AI 的能力与原理
  • 核心知识点：
  • 扩散模型（Diffusion）原理直觉（Stable Diffusion、DALL·E）
  • 文生图、图生图、视频生成（Sora、Seedance）
  • TTS / STT（语音合成与识别）
  • AI 代码生成（Copilot、Cursor、Trae）
  • 关联 ERP：用 AI 生成产品图、营销文案、报表解读
  • 主线项目：自动生成采购分析报告与图表（v0.9）
  • 实践：试用 Seedance 或文心一格生成一张图片，记录 Prompt 和结果
Day 15｜生成式 AI 小结 + 第三次小测
  • 复习：M3 全部知识点
  • 主线项目：完成"采购制度智能问答"完整项目（v1.0）
  • 实践：完成一个"企业制度问答 RAG"小项目
  • 考核：M3 周测

模块 M4：AI 工程化：数据、部署、Agent

Day 16｜AI 数据工程
  • 学习目标：理解 AI 项目中数据的全生命周期
  • 核心知识点：
  • 数据采集、清洗、标注、增强
  • 数据质量对模型的决定性影响
  • 数据合规与隐私（脱敏、联邦学习）
  • 数据飞轮（Data Flywheel）
  • 关联 ERP：ERP 系统是企业最大的数据来源，如何治理数据喂给 AI
  • 主线项目：盘点"智能采购助手"所需的数据清单与治理方式
  • 实践：找一个 ERP 业务场景，列出"如果要做 AI，需要哪些数据"清单
Day 17｜模型部署与 MLOps
  • 学习目标：理解模型如何从笔记本走向生产
  • 核心知识点：
  • 模型部署方式：API 服务、边缘部署、私有化
  • 推理优化（量化、蒸馏、剪枝）
  • MLOps 概念（类似 DevOps 但针对模型）
  • 大模型部署：vLLM、TensorRT-LLM
  • 模型监控与漂移（Drift）检测
  • 关联 ERP：AI 模型如何与 ERP 系统集成（API、消息队列、数据库直连）
  • 主线项目：把 RAG 问答部署成 ERP 可调用的 HTTP 服务（v1.1）
  • 实践：把 Day 15 的 RAG 用 FastAPI 包装成一个 HTTP 接口
Day 18｜AI Agent 与工具调用
  • 学习目标：理解 AI Agent 这一当前最热门的方向
  • 核心知识点：
  • Agent = LLM + 记忆 + 规划 + 工具调用
  • Function Calling / Tool Use 机制
  • 多 Agent 协作（CrewAI、AutoGen）
  • Agent 框架：LangChain、LlamaIndex、LangGraph
  • Agent 的局限与风险
  • 关联 ERP：ERP 智能助手 = Agent 调用 ERP API 完成下单、查库存
  • 主线项目：让 Agent 自动查价、查库存、下单（v1.2）
  • 实践：用 LangChain 实现一个能调用计算器工具的 Agent

模块 M5：AI 与企业 / ERP 结合

Day 19｜AI 在企业中的应用全景

八、AI × ERP 真实案例集

本章收录国内外头部企业在 ERP 各模块落地 AI 的真实案例，供学员参考技术选型与落地路径。每个案例包含：业务背景、AI 技术方案、集成方式、落地效果。

8.1 财务模块

案例 1：西门子 — 智能对账自动化
  • 业务背景：西门子全球每年处理数百万笔供应商对账，人工对账耗时长、差错率高，月结周期长达 10 天。
  • AI 技术方案：
  • 用 NLP + 规则引擎 自动匹配银行流水与 ERP 应付凭证
  • 模糊匹配（金额差异 < 0.5% 自动核销）+ 异常单据转人工
  • 基于 Transformer 的语义匹配 处理摘要文本不一致问题
  • ERP 集成：通过 SAP API 读取应付凭证，回写对账结果到 SAP FI 模块
  • 落地效果：对账自动化率 85%，月结周期缩短至 3 天，人工成本下降 60%
案例 2：沃尔玛 — 发票自动识别与录入
  • 业务背景：沃尔玛中国每年处理千万级供应商发票，人工录入效率低、合规风险高。
  • AI 技术方案：
  • OCR（文字识别）+ LLM 结构化提取 识别发票全字段
  • 与 ERP 采购订单、入库单三单匹配
  • 异常发票（金额不符、抬头错误）自动拦截并预警
  • ERP 集成：识别结果通过 API 写入 Oracle ERP 应付模块
  • 落地效果：发票处理时效从 2 天缩短至 2 小时，录入准确率 99.2%
案例 3：金蝶财务云 — 智能财报生成
  • 业务背景：集团企业财报合并涉及多准则、多币种，编制周期长。
  • AI 技术方案：
  • LLM 自动生成财报附注文字说明
  • 基于规则引擎 + 机器学习做合并抵消
  • 异常数据自动标注并给出调整建议
  • ERP 集成：金蝶云·星空财务模块原生集成 AI 能力
  • 落地效果：财报编制周期从 15 天缩短至 5 天

8.2 供应链模块

案例 4：京东 — 智能需求预测
  • 业务背景：京东 SKU 超千万，需求波动大（促销、季节、突发事件），传统统计模型预测误差高。
  • AI 技术方案：
  • 深度学习时序模型（LSTM + Transformer） 做销量预测
  • 融合促销活动、天气、节假日、竞品价格等外部特征
  • 分层预测（SKU → 品类 → 区域 → 全国）
  • ERP 集成：预测结果回写京东自研 ERP 的补货计划模块，驱动自动补货
  • 落地效果：预测准确率提升 15%，库存周转天数下降 8 天，缺货率降低 30%
案例 5：海尔 — 库存智能优化
  • 业务背景：海尔产品型号多、生命周期短，库存积压与缺货并存。
  • AI 技术方案：
  • 强化学习 优化安全库存水位
  • 聚类算法 对 SKU 按需求特性分群，差异化补货策略
  • LLM 解读库存报表，给出调货建议
  • ERP 集成：与海尔 COPIM（自研 ERP）库存模块实时联动
  • 落地效果：库存金额下降 12%，订单满足率提升至 98%
案例 6：联合利华 — 供应商风险预警
  • 业务背景：全球供应链中断事件频发（疫情、地缘冲突、自然灾害），需要提前识别供应商风险。
  • AI 技术方案：
  • 知识图谱 + 舆情 NLP 监控供应商新闻、财务、地缘风险
  • 图算法分析供应商网络的传导风险（二级供应商影响）
  • LLM 生成风险简报
  • ERP 集成：风险评分接入 SAP SRM 供应商管理模块
  • 落地效果：供应链中断响应时间从 72 小时缩短至 6 小时

8.3 生产制造模块

案例 7：宁德时代 — AI 视觉质检
  • 业务背景：电池极片缺陷检测要求极高（μm 级），人工质检漏检率高、招工难。
  • AI 技术方案：
  • CNN（卷积神经网络）+ 目标检测 识别极片划痕、异物、涂布不均
  • 边缘部署（产线 GPU 工控机），毫秒级推理
  • 缺陷数据回流持续训练（数据飞轮）
  • ERP 集成：质检结果写入 MES（制造执行系统），联动 ERP 质量模块生成质量报告
  • 落地效果：检测准确率 99.5%，漏检率 < 0.1%，人力节省 70%
案例 8：宝马 — 设备预测性维护
  • 业务背景：冲压车间设备非计划停机损失巨大（每分钟损失数万元）。
  • AI 技术方案：
  • 设备传感器时序数据 → LSTM 异常检测 预测故障
  • 剩余使用寿命（RUL）预测模型
  • 自动生成维护工单
  • ERP 集成：预测结果触发 SAP PM（设备维护）模块自动创建工单
  • 落地效果：非计划停机减少 40%，维护成本降低 25%
案例 9：三一重工 — 智能排产
  • 业务背景：多品种小批量生产，排产复杂度高，人工排产需数天。
  • AI 技术方案：
  • 混合整数规划 + 强化学习 优化生产排程
  • 考虑设备、人员、物料、交期多重约束
  • LLM 自然语言交互调整排产
  • ERP 集成：排产结果回写 SAP PP（生产计划）模块
  • 落地效果：排产时间从 3 天缩短至 2 小时，产能利用率提升 15%

8.4 人力资源模块

案例 10：IBM — 智能简历筛选
  • 业务背景：IBM 每年收到百万级简历，HR 初筛工作量巨大。
  • AI 技术方案：
  • NLP 语义匹配 简历与 JD 的匹配度评分
  • 实体提取识别技能、经验、教育背景
  • 偏见检测（避免性别、年龄歧视）
  • ERP 集成：与 IBM 自研 HCM 模块集成，自动推送候选人
  • 落地效果：简历筛选效率提升 5 倍，招聘周期缩短 30%
案例 11：华为 — 离职预测与人才保留
  • 业务背景：核心人才离职成本高，需要提前识别高风险员工。
  • AI 技术方案：
  • XGBoost 分类模型 预测离职概率（特征：绩效、加班、调薪、晋升、项目变更）
  • SHAP 值解释离职原因

10.2 三个"打通任督二脉"的深入类比

① 过拟合 ≈ 主数据"本地化过深"
你给某工厂做了一套高度定制的主数据规则，在本厂运行完美，但一复制到另一家工厂就全面报错。模型也一样——它把训练数据的"噪声"也背下来了，换个数据集就失效。对策：更丰富的样本、正则化、交叉验证（对应 ERP 里的"多工厂试点"）。

② RAG ≈ 会计"先查凭证再做账"
一个不查底稿、凭记忆做账的会计，迟早出错（幻觉）。RAG 就是给大模型配了一个"档案管理员"：回答问题前先检索企业内部制度、合同（对应"查凭证"），再据此作答。这是企业落地 AI 最关键的技术，因为它能把大模型的通用能力和你的私有数据结合起来。

③ Agent ≈ 从"计算器"升级为"数字员工"
传统软件（包括 ERP）是你操作它、它执行；而 Agent 是你给它一个目标，它自己规划步骤、调用工具（查库存 API、下单 API）、根据结果决定下一步。它像一名能自己走流程的采购员，而不是一个被动等指令的计算器。但也要给它"权限边界"（对应 ERP 的权限管理体系）。

十三、常见误区清单

学 AI 最容易踩的坑，提前避开。

# 常见误区 正确认知
1 "AI 就等于大模型（LLM）" 大模型只是 AI 的一个分支；AI 还包括预测模型、视觉、语音等
2 "数据越多越好" 数据质量比数量更重要；脏数据越多模型越差
3 "准确率 99% 就能上线" 要看业务容忍度、类别不平衡、分布是否一致；医疗/金融场景对误判极敏感
4 "AI 是黑箱，企业没法用" 随机森林、SHAP 等可提供解释；金融、审计场景需优先选可解释模型
5 "用了 AI 就不用管数据了" 恰恰相反，AI 项目 70–80% 工作量在数据
6 "模型训练一次就一劳永逸" 业务环境会变，模型会漂移，需持续监控与再训练
7 "大模型能替代 ERP" 大模型是增强 ERP，不是替代；ERP 是数据与流程的底座
8 "提示词是玄学" 提示词工程是有方法论的（角色/任务/示例/格式/思维链）
9 "AI 项目 = 算法项目" 实际是"数据 + 工程 + 业务理解"的综合项目，算法只是其中一环
10 "私有数据可以随便喂给公有云大模型" 有严重合规与泄密风险，需评估脱敏、私有化部署
11 "参数量越大模型越强" 大模型≠万能；小模型在特定任务上可能更省钱更准
12 "AI 会立刻取代人" 现阶段 AI 更多是"增强人"（Copilot 模式），决策仍需人把关

课程设计：基于 ERP 架构师知识背景定制，重应用、重场景、弱数学，目标是建立 AI 应用架构能力。
